# Daily Lumos 系統機制

> 本文件說明系統各項功能「實際上是怎麼運作的」，
> 包含背後的判斷規則。寫給想了解運作細節的人看。

---

## 一、登入機制

- 使用者用 **Google 帳號**登入（透過 Firebase Authentication）。
- 第一次登入時，系統會在資料庫建立一筆個人資料，記下名稱、Email、頭像。
- 登入狀態由 Firebase 自動記住，下次開啟 App 不需重新登入。
- 開發測試環境另有「跳過登入」機制，僅供本地測試，不影響正式環境。

## 二、每日抽卡機制

### 一天只能抽一張

- 系統用「**今天的日期**」判斷使用者今天抽過了沒。
- 資料庫每位使用者有一個 `lastDrawDate`（最後抽卡日期）欄位。
- 抽卡後，`lastDrawDate` 更新成今天；當天再進來就顯示已抽的卡，不能再抽。

### 跨日自動重置

- 「今天」用**裝置的本地日期**計算（不是 UTC），避免跨時區誤判。
- 到了午夜，倒數計時歸零，抽卡功能自動解鎖，新的一天可以再抽。

### 經文怎麼來

1. 系統從**聖經全 66 卷書**中隨機選出一卷、一節。
2. 先向線上服務 `bible-api.com` 取得該節經文。
3. 若線上取不到（網路問題或服務異常），改用 App 內建的**本地備援經文**。
4. 因此「一定抽得到卡」，不會因為外部服務掛掉而卡住。

### 抽卡為什麼很快

- 抽卡後**先把卡片顯示在畫面上**，讓使用者立刻看到結果。
- 「寫入資料庫」這個動作放到**背景**進行，不擋住畫面。

---

## 三、AI 經文解析機制

- 抽到卡片後，可以**翻面**查看 AI 對這節經文的白話解析。
- 翻面時，前端呼叫後端函式 `api/analyze.ts`。
- 後端把經文內容包進提示詞，呼叫 **Claude AI**，取得解析文字。
- 解析結果會存進資料庫，下次看同一張卡不必重新產生。
- 另可開啟「整章閱讀」視窗，讀這節經文所在的**整章內容**，支援直書閱讀模式。
- 整章內容向 `bible-api.com` 取得。**單章書卷**（俄巴底亞書、腓利門書、
  約翰二書、約翰三書、猶大書）需特別處理：這些書整本只有一章，API 會把
  「書代碼+1」誤解為「第 1 節」，故改用明確的節範圍 `1:1-N` 取得整章。

## 四、每日提醒推播機制（最複雜的部分）

### 整體流程

1. 使用者在「每日提醒設定」中開啟推播、設定提醒時間。
2. **外部排程器 cron-job.org 每分鐘**自動呼叫一次後端 `api/send-reminders.ts`。
3. 後端逐一檢查每位使用者，決定「現在這一刻」該不該推給他。
4. 對符合條件的人，透過 Firebase 推播通道送出通知。

> 為何用 cron-job.org：要讓提醒誤差控制在 1 分鐘內，排程器必須「每分鐘觸發、
> 且準時」。GitHub Actions 排程最小間隔 5 分鐘、整點常被延遲甚至丟棄，做不到，
> 故改用每分鐘精準觸發的 cron-job.org。

### 開啟推播時發生什麼

- 系統向使用者要求「通知授權」。
- 註冊一支背景小程式（Service Worker），它負責在 App 沒開時也能收通知。
- 取得這台裝置專屬的「推播識別碼」（FCM token），存進資料庫。

### 後端決定「該不該推」的判斷規則

後端撈出所有「**有開啟推播**」的使用者後，逐一套用以下檢查，
**任何一項不通過就跳過、不推播**：

| 檢查項目 | 規則 | 用意 |
|----------|------|------|
| 今天抽過卡了嗎 | 抽過 → 跳過 | 已經抽了就不打擾 |
| 今天通知過了嗎 | 通知過 → 跳過 | 同一天不重複轟炸 |
| 提醒時間到了嗎 | 還沒到 → 跳過 | 時間未到不提早推 |
| 是否超過補送視窗 | 超過 10 分鐘 → 跳過 | 避免推出過期的提醒 |
| 有沒有推播識別碼 | 沒有 → 跳過 | 沒識別碼無法送達 |

→ 全部通過，才會送出推播。

### 「補送視窗」是什麼

- 排程器每分鐘呼叫一次，正常情況提醒時間一到就推，誤差在 1 分鐘內。
- 補送視窗是**安全網**：萬一某幾次呼叫偶發失敗，規則允許在
  「**提醒時間到了之後的 10 分鐘內**」由後續呼叫補送。
- 例如設定 09:30，即使 09:30 那次呼叫失敗，09:31 的呼叫仍會補上。
- 但若超過 10 分鐘（已算過期提醒），就放棄不推。

### 推播時間可精確到「每分鐘」

- 使用者在設定畫面用「時 / 分」兩個選單組合提醒時間，可精確到任一分鐘
  （例如 08:00、08:17、21:45）。
- 排程器每分鐘觸發，足以準確命中任何分鐘設定。
- （早期版本曾限制為整點或半點共 48 個時段，那是 GitHub Actions 每 30 分鐘
  排程時代的限制；改用每分鐘排程後已開放到每分鐘。）

### 「先禱告再抽卡」的引導文案

- 推播文字共有 **6 則**，語氣溫暖、親切、口語、有帶領感。
- 每則都引導使用者「**先禱告、再抽卡**」，把今日箴言定位成主為你預備的禮物與方向。
- 每天依日期輪替一則：`索引 =（年＋月＋日的總和）÷ 6 的餘數`。
- 同一天所有人收到的是同一則。

六則完整文案如下（索引 0～5）：

| 索引 | 標題 | 內文 |
|------|------|------|
| 0 | 嘿，今天還沒和主說說話喔 | 先停下來，向主禱告一會兒，再抽今日箴言 — 領受這份為你預備的禮物。 |
| 1 | 主為你預備了今天的話 | 安靜下來，把心裡的事交給主，然後翻開卡片，看看祂給你的方向。 |
| 2 | 留三分鐘給自己，也給主 | 先禱告交託，再抽一張今日箴言 — 聽聽主今天想對你說什麼。 |
| 3 | 今天的箴言還在等你 | 別急，先和主禱告片刻，再來領受這句特別為你而寫的話。 |
| 4 | 新的一天，先深呼吸 | 把今天輕輕交給主禱告，然後抽一張卡，讓這份禮物陪你走下去。 |
| 5 | 主有話想對你說 | 先靜靜禱告，再翻開今日箴言 — 願這句話成為你今天的光與方向。 |

> 文案定義在 `api/send-reminders.ts` 的 `MESSAGES` 陣列；
> 修改文案時，請同步更新本表。

### 已送出後怎麼防止重複

- 成功送出後，把該使用者的 `lastNotifiedDate`（最後通知日期）標記成今天。
- 之後同一天的排程再跑，看到「今天通知過了」就會跳過。
- 若使用者的推播識別碼已失效，系統會自動清除它。

### 安全機制

- 排程器呼叫後端時需附帶一組密鑰（`CRON_SECRET`）。
- 後端會驗證這組密鑰，不符就拒絕，避免推播端點被外部任意呼叫。

## 五、「加到主畫面」教學機制

- 系統會自動**偵測使用者的作業系統**：iOS、Android、或電腦。
- 偵測方式：讀取瀏覽器資訊；iPad 會偽裝成 Mac，另用「觸控點數量」輔助判斷。
- **手機版**才會顯示「加到主畫面」教學，並依系統顯示對應的三步驟說明。
- **電腦版**不顯示教學、也不提供推播（推播主要為手機情境設計）。
- 系統也能判斷 App 目前是否已用「主畫面模式」開啟（即已安裝）。

## 六、功能導引教學機制

第一次登入的新使用者，系統會自動帶他認識每個核心功能，
採「黑色半透明遮罩挖空目標元素 + 旁註說明卡」的漸進式導覽。

### 何時自動顯示

- **判定依「版面寬度」**：窄版與寬版各記一個旗標（`tutorialSeenMobile` /
  `tutorialSeenDesktop`），同一帳號在窄版（手機）、寬版（桌機）各自第一次
  登入都會各教一次。
- 自動顯示要等**畫面與當日卡片載入完成**才啟動，避免挖空到還沒出現的元素；
  若使用者登入後不在抽卡頁，會先靜默切回抽卡頁再開始。
- 旗標讀取失敗或欄位不存在，一律視為「未看過」（會顯示教學）。

### 教學分手機版與桌機版

- 系統用**視窗寬度**判斷顯示哪一版（視窗寬 ≥ 1024px 為桌機/寬版，
  < 1024px 為手機/窄版），與 App 版面切換（底部 NavBar vs 左側 Sidebar）
  採同一個斷點，確保教學版本與當下實際看到的版面一致（例如桌機瀏覽器把
  視窗縮窄時，會走窄版教學、對位窄版的 NavBar）。版本在教學啟動當下鎖定，
  流程中不變。
  - **手機版（窄版）**：7 站（底部導覽、抽卡按鈕、卡片互動、倒數計時、
    使用者選單、每日提醒設定、加到主畫面）；若已安裝為主畫面 App，
    則少「加到主畫面」一站、變 6 站。
  - **桌機版（寬版）**：5 站（左側導覽、抽卡按鈕、卡片互動、倒數計時、使用者選單）。
- 「加到主畫面」站仍依「是否已安裝為 PWA」判定是否出現（與視窗寬度無關）。
- 手機教學講到使用者選單內的項目時，會自動替使用者展開選單再挖空，
  教學結束時自動收合。

### 展示站（卡片互動、倒數計時）的處理

- 「卡片互動」與「倒數計時」這兩站要介紹的真實元素（可翻面的卡片、倒數計時）
  都只在「抽完卡」後才出現，新使用者第一次登入時還沒抽卡、這些元素並不存在。
- 為了讓這兩站照常介紹功能、且進度號碼不跳號，教學在 spotlight 內放一個
  **展示用元件**，視覺比照真實元件、靜態呈現，**只活在教學裡** ——
  不碰真實頁面、不影響任何系統狀態，教學「下一步 / 上一步 / 略過 / 完成 / 關閉」
  時隨教學一起消失。
  - **卡片互動站**：放一張展示用箴言卡（固定範例經文，視覺比照真實卡片）。
    這張展示卡會**疊在「真實卡片區域」的實際位置上** —— 教學會量測真實
    卡片區容器的位置與大小，把展示卡渲染在原地，視覺上像是
    「在真實卡片的位置把卡片呈現給你看」，而不是飄在畫面正中央。桌機版
    真實卡片在右欄、手機版在畫面中間，兩種版面都各自貼合。spotlight
    挖空框也圍在這個位置。兩個互動點 ——（1）點一下卡片可翻面看 AI 解析、
    （2）點章節出處可讀整章原文 —— **以 ①② 兩行編號說明併入說明卡內呈現**
    （說明卡 = 站說明 + ①② 兩行，下方只有一塊面板）。展示卡本體上、對應
    這兩個互動點的位置（右上角 AI／翻面按鈕、左下角章節出處）各放一個
    金色小編號圓點 ①②，與說明卡內 ①② 兩行的序號圓點視覺一致，讓使用者
    能把卡片上的 ①② 對到說明卡內的 ①②。展示卡片是靜態的，不真的翻面、
    不呼叫 AI。
    （手機版垂直空間有限，①② 不另開獨立標註卡，避免堆疊蓋住展示卡底部
    的 ② 標記。）
    （手機版說明卡的擺位：真實卡片尺寸較大（280×400），手機螢幕放不下
    「全尺寸展示卡 + 說明卡 + ①② 兩個標記」—— 說明卡無論放上方或下方，
    都會壓到卡片某一角的編號標記。故**手機版站③把展示卡整體等比縮小到
    約 72%**，騰出垂直空間：縮小後的卡片仍置於真實卡片區域的中央（視覺上
    仍是「在原地呈現卡片」），spotlight 挖空框也圍在縮小後的範圍。
    縮小後，說明卡擺在卡片上方或下方就有足夠空間、不會壓到 ①② 標記。
    卡片內容、①② 標記、標記與 AI 鈕／章節出處的相對位置都隨卡片等比例
    縮放、保持正確。桌機版說明卡排在卡片側邊、空間足夠，不縮放，
    維持全尺寸。）
  - **倒數計時站**：放一個顯示固定範例時間（`23:59:59`）的展示用倒數計時。
    這個展示倒數會**疊在「抽卡按鈕」的實際位置上** —— 因為抽完卡後，
    真實倒數計時正是出現在抽卡按鈕原本的位置（手機版按鈕位置會換成倒數，
    桌機版則在左欄資訊區）。教學量測抽卡按鈕的位置與大小，把展示倒數
    渲染在原地，視覺上像「在真實倒數的位置把倒數呈現給你看」，不真的計時。
    展示倒數的暖米底盒會**完全不透明、且鋪滿整個 spotlight 挖空框**
    （與挖空框等大、等圓角），徹底蓋住底下露出的真實抽卡按鈕 ——
    使用者只看到乾淨的展示倒數，不會同時看到後面真實的抽卡按鈕。
- 因此這兩個展示站不會因「找不到目標」而被自動跳過；其餘站點若目標元素
  始終不存在，仍會自動跳過該站。

### 操作與結束

- 每一站都有「下一步 / 上一步」可前後移動，最後一站是「完成」；
  右上角固定有「略過導引」可隨時關閉。
- 點遮罩暗處不會關閉教學，只有控制鈕能操作。
- 教學「完成」或「略過」時，若這次是自動顯示，就把對應裝置旗標寫成「已看過」，
  之後不再自動彈出。寫入採「樂觀關閉」——點完成立即退場，旗標背景寫入，
  寫入失敗不阻斷使用者（下次登入可能再教一次，屬可接受降級）。
- 看過教學的使用者，仍可從使用者選單的「**功能導引**」入口隨時重看；
  手動重看不會改變任何旗標。

## 七、資料儲存機制

所有資料存在 Firebase Firestore。主要結構：

```
users（使用者集合）
 └─ 每位使用者一筆文件
     ├─ 個人資料：名稱、Email、頭像
     ├─ lastDrawDate     最後抽卡日期
     ├─ lastNotifiedDate 最後推播通知日期
     ├─ pushEnabled      是否開啟推播
     ├─ pushHour / pushMinute  提醒時間（時、分）
     ├─ fcmToken         推播識別碼
     ├─ tutorialSeenMobile  手機版功能導引是否已自動顯示過
     ├─ tutorialSeenDesktop 桌機版功能導引是否已自動顯示過
     └─ cards（卡片子集合）
         └─ 每張抽過的卡一筆：經文、主題、AI 解析等
```

## 八、測試環境與正式環境的隔離

- 「發送測試通知」功能由環境變數 `ENABLE_PUSH_TEST` 控制。
- 正式環境不設這個變數，後端的測試端點會直接回傳 404（等於不存在）。
- 因此**測試功能絕不會出現在正式環境**，使用者看不到、也無法觸發。
