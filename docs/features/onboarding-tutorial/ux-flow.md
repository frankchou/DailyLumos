> 本文件只定義「動線與互動」—— 逐站順序、導覽行為、spotlight 移動編排、

## 一、設計總綱

### 體驗基調
依 `design-system`,教學的調性是「溫暖陪伴、安靜引導」,**不是闖關**。動線設計原則:

- **可中斷、無壓力**:每一站都看得到「略過導引」,使用者隨時能離開。
- **單站單焦點**:一次只挖空一個目標,不讓使用者分心。
- **可逆**:除第一站外都能「上一步」回看,降低錯過內容的焦慮。
- **手機優先**:站點順序依手機實際版面由下而上、由主到次安排;桌機為對應簡化版。
- **不打斷主流程**:教學全程在抽卡頁版面上進行,不跳頁、不開其他 modal（D5）。

### 動線一句話
> 載入完成 → （必要時切回抽卡頁）→ 半透明遮罩升起 → 逐站 spotlight 移動 →
> 走到選單站時自動展開選單 → 最後一站「完成」或中途「略過導引」→ 遮罩落下,回到 App。

## 二、啟動前置流程（自動顯示情境）

對應 FR-1、EX-1、EX-12、D1。

```
登入流程完成
   │
   ▼
[判定] 對應裝置旗標是否為 true？
   │（tutorialSeenMobile / tutorialSeenDesktop,依 isMobile() 判定裝置）
   │
   ├─ 是（已看過）──────────────► 不啟動。結束。
   │
   └─ 否（未看過 / 旗標不存在 / 讀取失敗）
          │
          ▼
   步驟 1｜判定裝置版本
        以啟動當下 isMobile() 結果鎖定「手機版」或「桌機版」流程,
        流程進行中不再變更（EX-9）。
          │
          ▼
   步驟 2｜確認落在抽卡頁（D1 / FR-1.5 / EX-12）
        目前頁面 == 抽卡頁？
          ├─ 是 → 直接進步驟 3。
          └─ 否（落在「我的卡片冊」等）→ 程式自動切回抽卡頁,
               切換採一般換頁,不顯示遮罩、不顯示教學,
               待抽卡頁掛載後再進步驟 3。
          │
          ▼
   步驟 3｜等待載入就緒（FR-1.4 / EX-1）
        以下三條件全部成立才繼續:
          (a) user 登入狀態已確定
          (b) 抽卡頁已掛載、卡片區域容器 DOM 已存在
          (c) 當日卡片資料載入流程結束（無論「已抽過」或「尚未抽卡」）
        等待期間:不顯示遮罩,使用者看到的是正常抽卡頁。
        → 不設硬性逾時;若某條件遲遲不成立,教學就不啟動,
          App 仍完全可用（寧可不教,不可挖空到空元素）。
          │
          ▼
   步驟 4｜啟動教學
        半透明遮罩升起 → 進入手機版站① / 桌機版站①。
```

### 互動決策
- **切回抽卡頁時不顯示「正在準備教學」字樣**:保持安靜,避免讓使用者以為當機。
  換頁本身很快,接著遮罩升起即是明確的「教學開始」訊號。
- **遮罩升起動畫**:輕柔淡入（fade-in 調性,具體曲線交 UI）。不要瞬間黑屏,
  以免驚嚇——符合「安靜靈修」基調。

## 三、導覽互動規則（手機 / 桌機共用）

對應 FR-3、FR-7、D2、D4。

### 導覽控制列（每一站都常駐）
每個站點的文字說明卡上固定包含:

| 元件 | 出現時機 | 行為 |
|------|----------|------|
| 進度指示（如「3 / 7」） | 每一站 | 顯示「目前站序 / 本次總站數」。總站數依實際站點清單動態計算（見下）。 |
| 「上一步」 | 第 2 站起 | 回到前一站。第 1 站不顯示（或顯示為不可用,交 UI）。 |
| 「下一步」 | 第 1 站 ~ 倒數第 2 站 | 前往下一站。 |
| 「完成」 | 最後一站 | 取代「下一步」。結束教學。 |
| 「略過導引」 | 每一站（含最後一站） | 立即結束整個教學。措辭固定為「略過導引」（D4）。 |

### 進度指示的站數計算（重要,對應 FR-5.3 / AC-14）
- 進度的「總站數」= **本次實際會呈現的站點數**,在教學啟動當下就算定:
  - 手機 + 未安裝 PWA → 總數 7,進度顯示 1/7 ~ 7/7。
  - 手機 + 已安裝 PWA（isStandalone）→ 第⑦站不存在,總數 6,進度顯示 1/6 ~ 6/6。
  - 桌機 → 總數 5,進度顯示 1/5 ~ 5/5。
- 站數在單次流程中不變動,使用者不會看到「7」中途變「6」的跳動。

### 「下一步 / 上一步」的站間行為
- 點「下一步」:目前站文字卡淡出 → spotlight 平移/重塑到下一目標 → 下一站文字卡淡入。
  三段銜接要連貫,讓使用者「視線跟著光走」(spotlight 移動細節見第五節)。
- 點「上一步」:同樣的反向銜接。若上一站涉及「選單已展開」狀態,
  回退時選單須維持展開（見第六節編排）。
- 導覽期間連點防呆:站間轉場進行中,「下一步/上一步」短暫不可再觸發,
  避免 spotlight 還沒對位就被要求再跳(具體 debounce 交架構師)。

### 「略過導引」與「完成」的差異
- 兩者**結果相同**:遮罩落下、回到正常 App、若為自動顯示則寫入旗標(FR-6.4 / FR-7.3)。
- 差別僅在語意與使用者心理:「完成」是走到終點,「略過導引」是中途離開。
- 兩者都不需二次確認彈窗——教學是低風險操作,再加一層確認反而煩躁,
  且回訪可隨時從入口按鈕重看。

### 底層攔截（FR-3.5 / AC-24）
- 遮罩開啟期間,底層 App 一律不可互動;所有操作只能透過文字卡上的控制元件。
- **唯一例外**:教學自身為了挖空而「自動展開的使用者選單」——展開動作由教學觸發,
  使用者不需也不應手動去點選單(見第六節)。

### 點遮罩空白處的行為（FR-7.4 裁定）
- **不**讓「點遮罩暗處」關閉教學。理由:
  - 教學中使用者會頻繁點「下一步」,暗處誤觸關閉的風險高,體驗挫折。
  - 已有明確的「略過導引」控制元件,符合 FR-7.1 / AC-25。
- 點暗處可接受的回饋:無反應,或文字卡做一次輕微「呼吸」提示「請用下方按鈕」
  (是否要此回饋交 UI 斟酌,非必要)。

### 文字卡擺位原則（FR-3.6 / AC-28,動線層級的要求）
- 文字卡不得遮住被挖空的目標,且不得超出畫面。
- 目標在畫面**上半部** → 文字卡擺目標**下方**;目標在**下半部** → 擺**上方**。
- 手機底部導覽(站①)、底部選單項目等貼邊目標,文字卡一律往畫面中央側擺放。
- 精確的位移、箭頭指向、邊距交 UI 設計師;本文件只要求「不遮目標、不出血」。

## 四、手機版逐站動線（7 站,未安裝 PWA;已安裝則為 6 站）

裝置判定 `isMobile()` 為真。站序依「實際版面由下而上、由主功能到次功能」安排,
與 requirements 第四節一致。

| 站序 | 站名 | spotlight 目標 | 此站要傳達的重點 | 此站特殊互動 |
|------|------|----------------|------------------|--------------|
| ① | 底部導覽列 | 畫面底部導覽列(今日箴言／我的卡片冊) | 這裡切換兩個分頁:抽每日箴言、查看收藏的卡片冊 | 教學第一站。文字卡擺目標上方(目標貼底)。 |
| ② | 抽卡按鈕 | 抽卡頁的抽卡按鈕 | 每天可抽一張主為你預備的箴言卡 | spotlight 由底部往畫面中段上移。 |
| ③ | 卡片互動 | 整個卡片區域容器(見 FR-8) | 「抽完卡後,點卡片可翻面看 AI 解析、看整章原文」 | 固定挖空卡片區域容器,不論是否已抽卡(FR-8.4)。 |
| ④ | 倒數計時 | 抽卡頁的倒數計時元件 | 顯示距離下一次可抽卡還有多久 | spotlight 在卡片區域附近小幅移動。 |
| ⑤ | 使用者選單 | 右上角頭像按鈕 | 個人資訊、收藏統計與更多設定都在這 | **此站結束 → 下一步時自動展開選單**(見第六節)。 |
| ⑥ | 每日提醒設定 | 使用者選單內「每日提醒設定」入口 | 可設定每日推播提醒,提醒自己回來抽卡 | 進站前選單須已展開;spotlight 落在選單內項目。 |
| ⑦ | 加到主畫面 | 使用者選單內「加到主畫面」入口 | 把 App 加到主畫面,像原生 App 一樣使用 | 僅 `!isStandalone()` 顯示。**僅文字告知,不開 InstallGuide modal(D5)**。 |

### 手機版 spotlight 移動編排
```
站①底部導覽列      ── 光點在畫面底邊
   │ 下一步
站②抽卡按鈕        ── 光點上移到畫面中段
   │ 下一步
站③卡片區域         ── 光點放大涵蓋整個卡片容器
   │ 下一步
站④倒數計時        ── 光點縮小、在卡片區附近小幅移動
   │ 下一步
站⑤頭像按鈕        ── 光點移到右上角
   │ 下一步 ──► 觸發「自動展開使用者選單」(第六節步驟 A)
站⑥每日提醒設定    ── 選單已展開,光點落在選單內「每日提醒設定」
   │ 下一步
站⑦加到主畫面      ── 選單維持展開,光點落在選單內「加到主畫面」
   │ 完成 ──► 收合選單(第六節步驟 C) → 遮罩落下
```

### 已安裝 PWA(isStandalone)的差異
- 第⑦站整站不存在。第⑥站「每日提醒設定」即為最後一站,其控制鈕由「下一步」變「完成」。
- 進度指示總數為 6;站⑥顯示「6 / 6」。
- 「完成」後同樣走「收合選單 → 遮罩落下」。

## 五、桌機版逐站動線(5 站)

裝置判定 `isMobile()` 為假。桌機無推播、無「加到主畫面」,站數較少。

| 站序 | 站名 | spotlight 目標 | 此站要傳達的重點 | 此站特殊互動 |
|------|------|----------------|------------------|--------------|
| ① | 左側 Sidebar 導覽 | 左側 Sidebar 的導覽項目(今日箴言／我的卡片冊) | 這裡切換兩個分頁:抽每日箴言、查看收藏的卡片冊 | 教學第一站。文字卡擺 Sidebar 右側。 |
| ② | 抽卡按鈕 | 抽卡頁的抽卡按鈕 | 每天可抽一張主為你預備的箴言卡 | spotlight 由左欄移到主內容區。 |
| ③ | 卡片互動 | 整個卡片區域容器(見 FR-8) | 「抽完卡後,點卡片可翻面看 AI 解析、看整章原文」 | 固定挖空卡片區域容器(FR-8.4)。 |
| ④ | 倒數計時 | 左欄資訊區的倒數計時元件 | 顯示距離下一次可抽卡還有多久 | spotlight 移回左欄。 |
| ⑤ | 使用者選單 | Sidebar 底部 `UserSection` 使用者區塊 | 個人資訊、收藏統計與更多設定都在這 | 最後一站,控制鈕為「完成」。 |

### 桌機版 spotlight 移動編排
```
站①Sidebar 導覽   ── 光點在左欄上方導覽項目
   │ 下一步
站②抽卡按鈕        ── 光點移到主內容區
   │ 下一步
站③卡片區域         ── 光點放大涵蓋卡片容器
   │ 下一步
站④倒數計時        ── 光點移回左欄資訊區
   │ 下一步
站⑤UserSection    ── 光點移到 Sidebar 底部使用者區塊
   │ 完成 ──► 遮罩落下
```

### 桌機與手機動線的關鍵差異
| 面向 | 手機版 | 桌機版 |
|------|--------|--------|
| 站數 | 7 站(已安裝 6 站) | 5 站(固定) |
| 導覽元件 | 底部導覽列 | 左側 Sidebar |
| 選單站 | 站⑤⑥⑦,需自動展開選單挖選單內項目 | 僅站⑤,只挖 UserSection 區塊整體,**不需展開選單**(見第六節說明) |
| 推播站 | 有(站⑥) | 無 |
| 加到主畫面站 | 有條件(站⑦) | 無 |
| spotlight 主軸 | 由下而上 | 由左欄 ↔ 主內容區來回 |

> 桌機站⑤的目標是「`UserSection` 使用者區塊」本身(頭像/名稱那一塊),
> 介紹的是「點這裡可看到個人資訊與設定」,**不需要展開內層彈出選單**。
> 桌機的「功能導引 / 登出」是點 UserSection 後才彈出的次選單,教學不深入到那一層。
> 若 UI / 架構師認為桌機站⑤也該展開彈出選單,請回報總指揮再裁定——
> 本動線預設「桌機站⑤不展開」,因為桌機 5 站皆為單層介紹,保持簡潔。

## 六、使用者選單的自動展開編排(僅手機,對應 D3 / EX-10)

手機站⑤⑥⑦涉及使用者選單內的元素。選單預設是收合的,教學必須自動展開它,
否則站⑥⑦的挖空目標根本不存在於 DOM。

### 編排時序
```
步驟 A｜進入站⑥前展開(在站⑤點「下一步」時觸發)
   1. 站⑤(挖空頭像按鈕)使用者點「下一步」
   2. 教學程式自動展開使用者選單(等同替使用者點了頭像)
   3. 等選單展開動畫結束、選單內 DOM 就緒
   4. spotlight 重新對位到選單內「每日提醒設定」→ 進入站⑥
   ※ 使用者全程不需自己點頭像;遮罩仍攔截手動互動。

步驟 B｜站⑥ → 站⑦
   選單維持展開,spotlight 在選單內由「每日提醒設定」平移到「加到主畫面」。
   不收合、不重新展開。

步驟 C｜教學結束時收合
   使用者在最後一站(站⑦,或已安裝時的站⑥)點「完成」或任一站點「略過導引」
   → 教學程式自動收合使用者選單 → 再讓遮罩落下。
   → 使用者回到的是「選單收合」的乾淨抽卡頁,與教學前一致。
```

### 互動決策
- **展開時機選在「站⑤的下一步」而非「進站⑤時」**:站⑤要介紹的是「頭像按鈕」這個入口,
  此時選單應維持收合,使用者才看得懂「點這顆會打開選單」。選單在離開站⑤、
  前往站⑥的轉場中才展開,語意順暢:「點下去 → 選單打開了 → 裡面有這些」。
- **結束一定收合(步驟 C)**:不論「完成」或「略過導引」,都要把選單收回。
  教學不應留下「使用者沒主動打開卻開著的選單」這種非預期狀態。
- **「上一步」回退的選單狀態**:
  - 站⑦→站⑥:選單維持展開。
  - 站⑥→站⑤:選單須**收合**,回到站⑤「介紹頭像入口」的原始情境
    (站⑤的語意前提是選單收合)。
- **展開/收合期間的 spotlight**:選單展開動畫進行中,spotlight 不應停在錯位處。
  動線要求:等選單動畫結束、目標 DOM 穩定後,spotlight 才對位顯示下一站文字卡。
  轉場期間可短暫只留遮罩、暫不顯示文字卡(具體時序交架構師)。

## 七、非首次使用者「手動開啟」進入流程

對應 FR-2、FR-6.6、D6、US-3。

```
使用者自行操作:
  手機 → 點右上角頭像 → UserMenu 展開 → 點「功能導引」項目
  桌機 → 點 Sidebar 底部 UserSection → 彈出選單 → 點「功能導引」(位於「登出」之上)
   │
   ▼
步驟 1｜收合來源選單(FR-2.4 / AC-7)
   啟動教學前,先把使用者剛打開的那個選單收合,
   回到乾淨的抽卡頁版面,再升起遮罩。
   │
   ▼
步驟 2｜確認落在抽卡頁
   與第二節步驟 2 相同:若不在抽卡頁,先切回抽卡頁。
   (手動開啟通常使用者已在某頁操作,此步驟確保站點版面正確)
   │
   ▼
步驟 3｜直接啟動,不等待長載入
   手動開啟時抽卡頁通常已載入完成,不需第二節步驟 3 的完整等待;
   但仍須確認卡片區域容器 DOM 存在(站③要挖空它)。
   │
   ▼
步驟 4｜啟動對應裝置版本教學
   走與自動顯示完全相同的逐站動線。
```

### 互動決策
- **手動開啟不寫旗標(FR-6.6 / AC-20)**:重看教學不影響 `tutorialSeenMobile/Desktop`。
  本來是 `true` 維持 `true`,本來 `false` 也維持 `false`(雖然這情境少見)。
- **入口按鈕無「新功能」紅點/標示(D6)**:老使用者上線後已被自動教一次(EX-6),
  入口就是常駐的「功能導引」選單項,不需額外吸引注意的徽章。
- **入口按鈕對所有人皆顯示(FR-2.5)**:看過、沒看過的使用者都看得到,隨時可重看。

## 八、邊界情境的互動處理

對應 requirements 第七節 EX 清單,逐條給出 UX 層面的處理。

| 編號 | 情境 | UX 動線處理 |
|------|------|-------------|
| EX-1 | 啟動前畫面/卡片未載入完 | 第二節步驟 3:等三條件成立才升遮罩;等待期間顯示正常抽卡頁,不顯示任何教學元素。 |
| EX-2 | 手機已安裝 PWA | 第⑦站整站不存在;站⑥變最後一站、控制鈕為「完成」;進度總數為 6。見第四節。 |
| EX-3 | 中途關閉(略過導引) | 與「完成」同結果:若選單展開先收合 → 遮罩落下 → 自動顯示情境寫旗標。見第六節步驟 C。 |
| EX-4 | 旗標寫入 Firestore 失敗 | UX 不顯示任何錯誤提示給使用者;教學照常結束、遮罩落下、App 可用。下次登入可能再自動教一次,屬可接受降級。 |
| EX-5 | 旗標讀取失敗/欄位不存在 | 視為未看過,正常啟動自動教學。使用者無感。 |
| EX-6 | 既有老使用者首次登入 | 等同新使用者:自動教一次。入口按鈕無「新功能」標示(D6)。 |
| EX-7 | 教學進行中使用者登出 | 教學立即整體中止:遮罩、文字卡、若展開的選單一併移除,不可殘留在登入畫面。此情境不寫旗標(使用者未真正完成,且已離開帳號)。 |
| EX-8 | 進行中旋轉螢幕/縮放致目標位移 | spotlight 與文字卡須跟著目標重新對位;重算期間若短暫錯位,動線要求「寧可文字卡暫隱、待對位完成再顯示」也不可挖空到錯誤位置。具體重算策略交架構師。 |
| EX-9 | 桌機/手機臨界尺寸中途切換 | 不即時切版:以啟動當下裝置判定為準,流程跑完。使用者下次重新啟動才重新判定(FR-4.3)。 |
| EX-10 | 選單站挖空時選單未展開 | 由第六節自動展開編排處理:進站⑥前確保選單已展開、目標 DOM 就緒,spotlight 才對位。 |
| EX-11 | 看過手機版、改桌機首次登入 | `tutorialSeenDesktop` 未設定 → 自動顯示桌機版。兩裝置動線獨立。 |
| EX-12 | 自動觸發時使用者在「我的卡片冊」頁 | 第二節步驟 2(D1):先靜默切回抽卡頁,再升遮罩啟動教學。 |

### 補充:教學進行中使用者熄屏/切到背景再回來
- 屬於需求未明列、但 PWA 常見的情境。動線建議:教學狀態保留,使用者回到前景時
  仍停在原本那一站(遮罩、spotlight、選單展開狀態都還在)。不自動重啟、不自動關閉。
- 若回前景時 DOM 已變動(如被系統重繪),比照 EX-8 重新對位。
- 此為動線層建議,實作可行性請架構師確認,如不可行再回報總指揮。

## 九、與 UI 設計師的交接清單

以下項目本文件「只定義動線、未定義視覺」,需 UI 設計師依 `design-system` 補完:

1. **遮罩視覺**:半透明黑遮罩的透明度、挖空孔的形狀(矩形/圓角矩形)、
   挖空孔邊緣是否加金色光暈(`glow` 陰影候選,呼應設計系統)。
2. **文字說明卡樣式**:背景(暖米底 warm.bg / warm.cream)、圓角(rounded-2xl/3xl)、
   陰影(card)、指向目標的箭頭/缺口造型。
3. **導覽控制列視覺**:「上一步 / 下一步 / 完成 / 略過導引」四顆鈕的視覺層級——
   建議「下一步/完成」為主要動作(金色點綴),「略過導引」為弱化的次要文字鈕,
   「上一步」為次要鈕。最終層級交 UI。
4. **進度指示形式**:「3 / 7」用數字、圓點、或進度條;站數會在 6/7 間變動,
   形式需能優雅呈現不同總數(避免固定 7 個點的設計)。
5. **轉場動畫**:spotlight 平移/縮放、文字卡淡入淡出、遮罩升起落下的動畫曲線,
   須符合 design-system「輕柔緩和、不突兀」,用 framer-motion。
6. **選單自動展開的動畫銜接**:站⑤→⑥ 選單展開時,spotlight 如何優雅地
   「等選單開好再對位」的視覺過渡。
7. **點遮罩暗處的回饋**:本文件建議「無反應或文字卡輕微呼吸提示」,是否採用、
   如何呈現交 UI。
