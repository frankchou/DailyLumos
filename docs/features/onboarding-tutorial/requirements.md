# 功能導引教學（Onboarding Tutorial）— 需求規格

功能代號：`onboarding-tutorial`
撰寫角色：產品經理 / 商業分析
文件狀態：待總指揮審閱 → 交架構師與設計層

---

## 一、功能目標與背景

### 背景
Daily Lumos 是每日箴言抽卡 PWA。目前介面雖然簡潔，但對新使用者而言，
許多核心互動並非一望即知，例如：

- 卡片可「翻面」看 AI 解析與整章原文。
- 主畫面有「倒數計時」表示下一次可抽卡的時間。
- 推播提醒、加到主畫面等功能藏在使用者選單裡。

新使用者若沒被引導，很可能只抽一次卡就離開，沒體會到收藏、解析、每日回訪
這些真正留住人的價值。

### 目標
1. 讓第一次登入的使用者，在開始使用前先快速認識每個核心功能。
2. 採用業界常見的「遮罩挖空 + 旁註說明」漸進式導覽（spotlight / coachmark）。
3. 看過教學的使用者不再被打擾；想複習的人可隨時自行重看。
4. 手機與桌機版面差異大，需各自提供對應版本的導覽。

### 非目標（邊界）
- 本規格不�定義具體視覺樣式（遮罩透明度、字體、動畫）→ 交設計層與 `design-system`。
- 不涉及技術實作選型（如自製 vs. 第三方導覽套件）→ 交架構師。
- 不含教學內容的多語系（目前全站繁體中文，維持單一語言）。

## 二、使用者故事

- **US-1**：身為第一次登入的新使用者，我希望登入後系統自動帶我認識每個功能，
  這樣我不用自己摸索就知道怎麼用這個 App。
- **US-2**：身為已用過 App 的回訪使用者，我不希望每次登入都被教學打斷，
  教學應該只出現一次。
- **US-3**：身為想複習或當初跳過教學的使用者，我希望能在使用者選單裡
  自己重新打開教學。
- **US-4**：身為手機使用者，我希望教學介紹的是我手機上實際看得到的元素
  （底部導覽、推播、加到主畫面）。
- **US-5**：身為桌機使用者，我希望教學介紹的是桌機版面（左側 Sidebar），
  不要出現我用不到的手機功能。
- **US-6**：身為剛登入、還沒抽過卡的新使用者，當教學講到「卡片互動」時，
  即使卡片還沒出現，我也能透過文字說明知道卡片之後能做什麼。
- **US-7**：身為使用者，我希望教學進行到一半可以隨時關閉，
  不被強迫看完。

## 三、詳細功能需求

### FR-1 顯示時機
- **FR-1.1** 第一次登入的使用者：登入流程完成後，自動啟動教學。
- **FR-1.2** 非第一次登入的使用者：不自動顯示，僅能由入口按鈕手動開啟。
- **FR-1.3** 「第一次」的判定依「裝置類型」而非單純帳號層級，見 FR-6。
- **FR-1.4** 自動顯示必須等到**主畫面與當日卡片狀態載入完成後**才開始，
  避免挖空到尚未 render 的元素。判定條件包含：
  - 使用者登入狀態確定（`user` 已就緒）。
  - 主畫面（抽卡頁）已掛載、卡片區域 DOM 已存在。
  - 當日卡片資料的載入流程結束（不論結果是「已抽過」或「尚未抽卡」）。
- **FR-1.5** 自動顯示僅在「抽卡頁 / 今日箴言」頁觸發；若登入後落在其他頁面，
  教學等回到抽卡頁再啟動，或先切回抽卡頁再啟動（最終行為交架構師與 UX 決定，
  本規格要求：教學的所有站點都基於抽卡頁版面）。

### FR-2 入口按鈕
- **FR-2.1** 按鈕標籤：**「功能導引」**。
- **FR-2.2** 手機：加入 `UserMenu`（頭像下拉選單）的選單項目。
- **FR-2.3** 桌機：加入 `Sidebar` 的 `UserSection` 彈出選單
  （目前該選單只有「登出」，需擴充，置於「登出」之上）。
- **FR-2.4** 點擊後立即啟動對應裝置版本的教學；若選單為展開狀態，
  啟動教學前先收合選單。
- **FR-2.5** 入口按鈕在「已看過教學」與「未看過教學」狀態下皆顯示
  （回訪使用者也要能重看）。

### FR-3 遮罩與挖空互動
- **FR-3.1** 教學啟動時，以一塊覆蓋整個畫面的黑色半透明遮罩蓋住 App。
- **FR-3.2** 遮罩會「挖空」當前站點要介紹的目標元素（該元素正常顯示、
  其餘變暗），並在目標元素旁顯示文字說明卡。
- **FR-3.3** 一次只呈現一個站點；提供「下一步 / 上一步」在站點間移動，
  最後一站提供「完成」。
- **FR-3.4** 每個站點都要能「跳過 / 關閉」整個教學（FR-7）。
- **FR-3.5** 遮罩開啟期間，底層 App 的互動被遮罩攔截
  （使用者不能誤觸底層按鈕），導覽僅透過教學自身的控制元件操作。
- **FR-3.6** 文字說明卡的位置需避免超出畫面、避免遮住被挖空的目標元素；
  目標靠近螢幕邊緣時自動調整方位（具體擺位邏輯交設計層 / 架構師）。

### FR-4 裝置區分
- **FR-4.1** 教學以 `src/lib/platform.ts` 既有的 `isMobile()` / `detectOS()`
  判定裝置，顯示對應版本。
- **FR-4.2** 手機版與桌機版的站點清單、挖空目標、版面皆不同（見第四、五節）。
- **FR-4.3** 裝置判定於教學啟動當下進行；單一教學流程進行中不需處理
  視窗中途由桌機尺寸縮成手機尺寸的即時切換（屬邊界情境，見第七節）。

### FR-5 「加到主畫面」站的連動（僅手機）
- **FR-5.1** 手機版第 7 站「加到主畫面」沿用 `UserMenu` 既有
  `showInstallItem = isMobile && !isStandalone()` 的判斷邏輯。
- **FR-5.2** 若使用者**尚未**加入主畫面（`!isStandalone()`）：顯示此站，
  讓使用者知道有「加到主畫面」功能。
- **FR-5.3** 若使用者**已**加入主畫面（`isStandalone()` 為真）：此站隱藏，
  手機版站點數由 7 降為 6，「下一步 / 上一步」與進度指示需相應調整。
- **FR-5.4** 桌機版本無此站。

### FR-6 「看過教學」的記錄
- **FR-6.1** 教學完成或關閉的紀錄存於 Firestore `users` 文件，
  與推播設定相同位置、跟著帳號走。
- **FR-6.2** 使用兩個獨立布林旗標：
  - `tutorialSeenMobile`：手機版教學是否已自動顯示過。
  - `tutorialSeenDesktop`：桌機版教學是否已自動顯示過。
- **FR-6.3** 自動顯示判定：
  - 手機裝置登入時，`tutorialSeenMobile` 不為 `true` → 自動顯示手機版教學。
  - 桌機裝置登入時，`tutorialSeenDesktop` 不為 `true` → 自動顯示桌機版教學。
- **FR-6.4** 旗標寫入時機：教學「完成最後一站」或「使用者中途關閉」時，
  將對應裝置旗標設為 `true`（兩者皆視為「已看過」，不再自動彈出）。
- **FR-6.5** 同一帳號在手機與桌機各自第一次登入都會各自自動教一次，互不影響。
- **FR-6.6** 手動透過入口按鈕開啟教學，**不改變**任何旗標
  （重看不應影響自動顯示紀錄；本來就 `true` 維持 `true`）。
- **FR-6.7** 旗標讀取失敗或欄位不存在時，視為「未看過」（預設教學會顯示），
  但寫入失敗不可阻斷使用者繼續使用 App（見第七節）。

### FR-7 跳過與關閉
- **FR-7.1** 教學任一站點都提供關閉方式（如關閉鈕、跳過鈕）。
- **FR-7.2** 關閉後遮罩消失，回到正常 App 畫面。
- **FR-7.3** 若此次為「自動顯示」，關閉時依 FR-6.4 寫入對應旗標。
- **FR-7.4** 是否允許點遮罩空白處關閉，交設計層 / UX 決定；
  本規格要求至少要有一個明確的關閉控制元件。

## 四、手機版教學站點清單（共 7 站）

裝置判定為手機（`isMobile()` 為真）時使用。

| 站序 | 站點名稱 | 挖空目標 | 說明文字重點 | 顯示條件 |
|------|----------|----------|--------------|----------|
| ① | 底部導覽列 | 畫面底部的導覽列（今日箴言／我的卡片冊） | 介紹兩個分頁：抽每日箴言、查看收藏的卡片冊 | 永遠 |
| ② | 抽卡按鈕 | 抽卡頁的抽卡按鈕 | 每天可抽一張箴言卡 | 永遠 |
| ③ | 卡片互動 | 整個卡片區域（見 FR-8 文字說明處理） | 「抽完卡後，點卡片可翻面看 AI 解析、看整章原文」 | 永遠 |
| ④ | 倒數計時 | 抽卡頁的倒數計時元件 | 顯示距離下一次可抽卡的時間 | 永遠 |
| ⑤ | 使用者選單 | 右上角頭像按鈕 | 個人資訊、收藏統計與更多設定都在這 | 永遠 |
| ⑥ | 每日提醒設定 | 使用者選單中的「每日提醒設定」入口 | 可設定每日推播提醒，提醒自己回來抽卡 | 永遠（手機） |
| ⑦ | 加到主畫面 | 使用者選單中的「加到主畫面」入口 | 把 App 加到主畫面，像原生 App 一樣使用 | 僅 `!isStandalone()` 時顯示（FR-5） |

> 站⑤⑥⑦涉及使用者選單內的項目，教學流程中可能需要先展開使用者選單
> 才能挖空選單內元素 —— 此展開行為由實作處理，本規格僅要求挖空目標在站點
> 呈現時必須是可見的。

裝置判定為桌機（`isMobile()` 為假）時使用。桌機無推播、無「加到主畫面」。

| 站序 | 站點名稱 | 挖空目標 | 說明文字重點 | 顯示條件 |
|------|----------|----------|--------------|----------|
| ① | 左側 Sidebar 導覽 | 左側 Sidebar 的導覽項目（今日箴言／我的卡片冊） | 介紹兩個分頁：抽每日箴言、查看收藏的卡片冊 | 永遠 |
| ② | 抽卡按鈕 | 抽卡頁的抽卡按鈕 | 每天可抽一張箴言卡 | 永遠 |
| ③ | 卡片互動 | 整個卡片區域（見 FR-8 文字說明處理） | 「抽完卡後，點卡片可翻面看 AI 解析、看整章原文」 | 永遠 |
| ④ | 倒數計時 | 左欄資訊區的倒數計時元件 | 顯示距離下一次可抽卡的時間 | 永遠 |
| ⑤ | 使用者選單 | Sidebar 底部 `UserSection` 的使用者區塊 | 個人資訊、收藏統計與更多設定都在這 | 永遠 |

## 六、FR-8 「卡片互動」站的特別處理

- **FR-8.1** 第一次登入的新使用者尚未抽卡，「翻面看解析 / 看原文」所對應的
  卡片互動元件可能尚未 render，無法精準挖空。
- **FR-8.2** 因此「卡片互動」站固定**挖空整個卡片區域容器**（無論卡片是否已抽出），
  而非挖空不存在的子元素。
- **FR-8.3** 說明文字固定為純文字引導：
  「抽完卡後，點卡片可翻面看 AI 解析、看整章原文」。
- **FR-8.4** 不論使用者當下是否已抽過卡，此站行為一致（皆挖空卡片區域 + 同一段文字），
  以保持手機 / 桌機、自動 / 手動情境下的一致體驗。

## 七、邊界情境與例外處理

| 編號 | 情境 | 預期處理 |
|------|------|----------|
| EX-1 | 自動教學啟動前畫面 / 卡片尚未載入完成 | 等待載入完成再啟動（FR-1.4），不可挖空到未 render 的元素 |
| EX-2 | 手機已加入主畫面（`isStandalone()`） | 手機版隱藏第⑦站，站數變 6，進度與導覽相應調整（FR-5.3） |
| EX-3 | 使用者中途關閉教學 | 遮罩消失；若為自動顯示則寫入對應旗標，視為已看過（FR-7.3） |
| EX-4 | 旗標寫入 Firestore 失敗（網路 / 權限問題） | 不可阻斷使用者操作；教學照常結束。可記錄錯誤，下次登入可能再次自動顯示，屬可接受降級 |
| EX-5 | 旗標讀取失敗或欄位不存在 | 視為「未看過」，預設顯示教學（FR-6.7） |
| EX-6 | 既有使用者（功能上線前已有帳號）首次登入 | `users` 文件無旗標欄位 → 視為未看過 → 會自動顯示一次教學（符合預期，等同新使用者待遇） |
| EX-7 | 教學進行中使用者登出 | 教學遮罩須一併關閉，不可殘留在登入畫面上 |
| EX-8 | 教學進行中使用者旋轉螢幕 / 縮放視窗導致目標元素位移 | 挖空框需能重新對位到目標元素；至少不可挖空到錯誤位置（具體重算策略交架構師） |
| EX-9 | 視窗在桌機 / 手機臨界尺寸間中途切換 | 單一教學流程不處理即時切版；以啟動當下的裝置判定為準（FR-4.3）。下次重新啟動才重新判定 |
| EX-10 | 使用者選單內元素（站⑤⑥⑦ / 桌機⑤）在挖空時選單未展開 | 該站呈現時須確保選單已展開、目標可見，否則挖空無意義 |
| EX-11 | 同一使用者已看過手機版、改用桌機首次登入 | `tutorialSeenDesktop` 仍為未設定 → 自動顯示桌機版（FR-6.5） |
| EX-12 | 自動教學觸發時使用者已切換到「我的卡片冊」頁 | 教學站點皆基於抽卡頁版面，需確保啟動時位於抽卡頁（FR-1.5） |

## 九、待釐清問題（回報總指揮）

1. **自動教學的頁面前提**：登入後若使用者預設不在抽卡頁，教學是要「先自動切到
   抽卡頁再啟動」，還是「等使用者自己回到抽卡頁才啟動」？建議前者（強制切回），
   體驗較完整，但需 UX / 架構師確認。
2. **進度指示形式**：站點之間是否要顯示「3 / 7」之類的進度點？本規格未硬性規定，
   建議交設計層，但會影響 AC-14（站數變動時的指示）。
3. **使用者選單在站⑤⑥⑦的展開行為**：教學是否要「自動幫使用者展開選單」並挖空
   選單內項目？若是，選單展開動畫與挖空對位的時序需架構師處理。建議自動展開，
   否則使用者選單內的項目無法被挖空介紹。
4. **跳過按鈕的措辭與位置**：是否在第一站就顯眼提供「跳過教學」？涉及文案與 UX。
5. **「加到主畫面」站與既有 `InstallGuide` 的關係**：教學第⑦站只是「告知有此功能」，
   還是要做成點下去直接開啟既有 `InstallGuide` modal？建議僅告知（與規格 FR-5.2 一致），
   避免教學中途彈出另一個 modal 打斷流程，但請確認。
6. **回訪使用者的入口按鈕是否需任何「新功能」標示**：功能首次上線時，老使用者會
   被自動教一次（EX-6），因此可能不需額外標示；確認即可。
