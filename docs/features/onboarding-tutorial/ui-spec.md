## 〇、範圍與前提

本文件**只定義視覺**：遮罩、挖空、說明卡、按鈕、進度指示、入口按鈕的外觀與狀態。
動線邏輯（站點順序、切站時機、選單展開時序、挖空對位演算法）**不在本文件**，交 UX / 架構師。

> 注意：撰寫本規格時，feature 資料夾尚無 UX 的 `ux-flow.md`。
> 本文件已盡量以視覺中立方式描述，文末「與 UX 需對齊事項」列出所有依賴 UX 決策的點。
> 若 UX 動線與此處假設不符，視覺尺寸可能需微調。

## 一、黑色遮罩（Overlay / Backdrop）

| 屬性 | 規格 |
|------|------|
| 顏色 | `rgba(44, 31, 20, 0.72)` —— 以 `warm.dark`(#2C1F14) 為基底的暖黑，**非純黑**，與暖米調性一致 |
| 透明度 | 72%（被挖空區以外的全畫面） |
| 模糊 | 遮罩本體**不加 backdrop-blur**。底層 App 已有不少 blur 元件，再疊模糊會顯髒、且效能負擔大。改以「暗化 + 挖空亮區」製造聚焦對比即可 |
| 覆蓋範圍 | `position: fixed; inset: 0;`，覆蓋整個 viewport |
| 層級 | `z-index: 70`（高於 UserMenu 下拉的 `z-50`、Sidebar 的 `z-40`，確保蓋住所有既有 UI；說明卡再更高，見第三節） |
| 進場動畫 | `opacity 0 → 1`，`duration 0.35s`，`ease-out`（沿用 `fade-in` 節奏） |
| 退場動畫 | `opacity 1 → 0`，`duration 0.3s`，`ease-out` |
| 互動攔截 | 遮罩層 `pointer-events: auto` 攔截所有點擊，使用者無法誤觸底層 App（對應 FR-3.5 / AC-24） |

### 挖空（Spotlight）的視覺實作建議

- 採「**SVG mask** 或 **box-shadow 擴散法**」開洞，由架構師選型；本文件只規定外觀結果。
- 視覺結果：被挖空的目標元素區域**完全不被暗化**（顯示原本亮度），其餘區域套用上述 72% 暖黑。
- 挖空形狀為**圓角矩形**，包住目標元素的 bounding box。

## 二、挖空區（Spotlight）視覺處理

| 屬性 | 規格 |
|------|------|
| 形狀 | 圓角矩形，貼合目標元素 bounding box |
| 留白（padding） | 目標元素四周外推 **8px**（手機）／ **10px**（桌機），讓挖空框不貼死元素邊緣 |
| 圓角 | 挖空框圓角 = `目標元素自身圓角 + 4px`；目標無圓角時固定 **12px**。卡片區域（站③）等大圓角元素則用 `20px`，呼應 `rounded-2xl/3xl` |
| 邊框 | 挖空框外緣 `1px solid rgba(212,168,83,0.55)`（金色細線），讓亮區與暗區之間有典雅分界，不是生硬的切邊 |
| 光暈 | 挖空框外圍套 `glow` token：`0 0 20px rgba(212,168,83,0.4)`，金色柔光向暗區擴散，引導視線 |
| 光暈動態 | 採輕microscopic 呼吸效果：光暈強度在 `rgba(...,0.3)` ↔ `rgba(...,0.5)` 間緩慢脈動，週期 **2.4s**，`ease-in-out`。比既有 `pulse-glow`(2s) 略慢、幅度更收斂，維持「安靜」調性 |
| 切站位移動畫 | 換站時挖空框以 `framer-motion` 平滑補間到新位置：`duration 0.4s`，`ease: [0.22, 0.61, 0.36, 1]`（柔和 ease-out）。位置/尺寸同時補間，不要瞬移 |
| 目標元素位移重算 | 旋轉螢幕 / 捲動導致目標位移時，挖空框需重新對位（EX-8，邏輯交架構師）；視覺上沿用上述補間動畫平滑跟隨 |

### 各站挖空目標的圓角對照（視覺參考，實際以元素 bounding box 為準）

| 站 | 挖空目標 | 建議挖空框圓角 |
|----|----------|----------------|
| 卡片互動站 | 整個卡片區域容器 | 20px |
| 抽卡按鈕 | 按鈕 | 元素圓角 +4px |
| 底部導覽列 / Sidebar 導覽 | 導覽列容器 | 16px |
| 頭像按鈕 | 圓形頭像 | 做成**圓形挖空**（border-radius 50%），不用矩形 |
| 選單內項目（每日提醒 / 加到主畫面 / Sidebar 使用者區） | 單一選單列 | 12px |
| 倒數計時 | 計時元件 | 12px |

## 三、說明卡（Coachmark / Tooltip）

說明卡是教學的核心溝通元件，承載標題、說明文字、進度、導覽按鈕。

### 3.1 外觀

| 屬性 | 規格 |
|------|------|
| 背景 | `rgba(253,248,240,0.98)`（`warm.bg` 近實心），沿用 UserMenu 下拉選單的背景處理 |
| 背景模糊 | `backdrop-filter: blur(12px)`（與 UserMenu / Sidebar 選單一致） |
| 邊框 | `1px solid rgba(212,168,83,0.25)` |
| 圓角 | `rounded-2xl`（16px） |
| 陰影 | `card`：`0 8px 32px rgba(61,43,31,0.15)` |
| 寬度 | 手機 `min(88vw, 320px)`；桌機固定 `360px` |
| 內距 | 手機 `20px`；桌機 `24px` |
| 層級 | `z-index: 80`（高於遮罩 `70`，確保說明卡永遠在最上層） |

### 3.2 內部排版（由上而下）

1. **頂端站點小標（選用）**
   - 字型 `font-display`（Cinzel），`font-size 11px`，`letter-spacing 0.18em`，`color #C4A882`。
   - 內容為站點英文代稱（如 `DAILY VERSE`、`YOUR CARDS`），文字由文案提供。
   - 若文案不提供英文代稱，此列省略，不留空白。

2. **標題**
   - 字型 `font-serif`，`font-size 17px`（手機）/ `18px`（桌機），`font-weight 600`，`color #3D2B1F`。
   - 行高 `1.4`。文字由文案提供。

3. **說明內文**
   - 字型 `font-sans`，`font-size 14px`，`color #8B6E5A`，行高 `1.7`（寬鬆，符合留白原則）。
   - 與標題間距 `8px`。文字由文案提供。
   - 卡片互動站固定文字見 requirements FR-8.3，UI 不改動文字。

4. **分隔線**
   - `1px solid rgba(212,168,83,0.15)`，上下間距 `16px`。沿用 UserMenu 內分隔線樣式。

5. **底部列**：左側進度指示（第四節）＋ 右側導覽按鈕（第五節），`flex justify-between items-center`。

### 3.3 指向箭頭（Arrow / Beak）

| 屬性 | 規格 |
|------|------|
| 形狀 | 三角形小箭頭，從說明卡邊緣指向被挖空元素 |
| 尺寸 | 底邊 `14px`、高 `8px` |
| 顏色 | 與說明卡同色 `rgba(253,248,240,0.98)`；朝挖空側的兩條斜邊帶 `1px` 同色描邊 `rgba(212,168,83,0.25)`，與卡片邊框接續 |
| 方位 | 可朝上 / 下 / 左 / 右，依說明卡相對挖空元素的位置自動選擇（見 3.4 擺位策略） |
| 對齊 | 箭頭尖端對齊挖空元素的中心軸（水平或垂直），但箭頭根部需保持距說明卡圓角至少 `16px`，避免壓在圓角上 |
| 特例 | 說明卡因空間不足置於畫面正中、無法貼近目標時（見 3.4），**隱藏箭頭**，改由挖空區光暈承擔指向 |

### 3.4 擺位策略（手機 / 桌機）

擺位「演算法」由架構師實作，本文件規定**視覺優先順序與安全邊界**：

**共同安全規則**
- 說明卡與挖空框之間留 `12px` 間隙（含箭頭空間）。
- 說明卡距 viewport 邊緣至少 `16px`（手機）/ `24px`（桌機）安全邊距。
- 說明卡**不得遮住挖空目標**（對應 FR-3.6 / AC-28）。
- 說明卡需避開手機瀏覽器底部安全區，預留 `env(safe-area-inset-bottom)`。

**手機擺位優先序**
1. 目標在畫面上半 → 說明卡置於目標**下方**，箭頭朝上。
2. 目標在畫面下半（如底部導覽列、抽卡按鈕） → 說明卡置於目標**上方**，箭頭朝下。
3. 目標為頭像（右上角） → 說明卡置於目標**下方偏左**，靠右對齊但不超出右安全邊距。
4. 上下皆塞不下（目標太大，如卡片互動站佔滿畫面） → 說明卡浮於畫面**底部置中**（貼近底部安全區），隱藏箭頭，靠挖空光暈指向。

**桌機擺位優先序**
1. 目標在版面右側區域 → 說明卡置於目標**左側**，箭頭朝右。
2. 目標在 Sidebar（畫面最左，如導覽 / 使用者區） → 說明卡置於目標**右側**，箭頭朝左。
3. 目標偏上 / 偏下時，垂直方向以「對齊目標中心、但不超出上下安全邊距」收斂。
4. 卡片互動站等大目標 → 說明卡置於卡片右側固定欄位，箭頭朝左；若右側空間不足則置於下方。

### 3.5 動畫

| 場景 | 動畫 |
|------|------|
| 說明卡首次進場 | `opacity 0→1`＋`scale 0.96→1`＋`y +8→0`，`duration 0.25s`，`ease-out`（沿用 UserMenu 下拉節奏） |
| 切站（同一張卡換內容） | 舊內容 `opacity 1→0`(0.12s) → 卡片移動到新位置(0.4s, 與挖空框同步) → 新內容 `opacity 0→1`(0.18s)。內容淡出淡入，外框平滑移動，不整張瞬移 |
| 退場 | `opacity 1→0`＋`scale 1→0.96`，`duration 0.2s` |

## 四、進度指示

採「**點 + 數字**」複合形式，置於說明卡底部列左側。

| 屬性 | 規格 |
|------|------|
| 數字文字 | `font-sans`，`font-size 12px`，`color #C4A882`，格式 `當前 / 總數`（如 `3 / 7`） |
| 圓點 | 一排小圓點，每點直徑 `6px`，間距 `5px` |
| 當前點 | 直徑 `6px`，實心 `#D4A853`，外加 `glow` 微光（`0 0 6px rgba(212,168,83,0.5)`） |
| 已完成點 | 實心 `rgba(212,168,83,0.55)` |
| 未到達點 | 實心 `rgba(196,168,130,0.35)`（淡 `text-light`） |
| 排列 | 數字在左、圓點在右，`gap 8px`，垂直置中 |
| 站數動態 | 總數依 requirements FR-5.3 動態變化（手機 7 或 6 站）。圓點數量與數字分母**隨實際站數渲染**，不可寫死。手機已安裝 PWA → 渲染 6 點、分母為 6 |
| 切站動畫 | 當前點移動時，舊點縮回 `0.55` 透明度、新點放大並亮起，`duration 0.25s`，`ease-out` |

> 桌機固定 5 站、手機 6 或 7 站。圓點數量上限 7，排成單列不會過寬（最寬約 7×6 + 6×5 = 72px），無需換行。

## 五、導覽按鈕

說明卡底部列右側，依站點位置顯示不同組合。**三種視覺層級**：

### 5.1 按鈕層級與樣式

**主按鈕（Primary）—— 「下一步」/「完成」**

| 狀態 | 樣式 |
|------|------|
| 預設 | 背景漸層 `linear-gradient(135deg, #F0D08A, #D4A853)`；文字 `#4A2800`（沿用 UserMenu 頭像 fallback 的金底深字組合）；`font-sans` `14px` `font-weight 600`；內距 `8px 18px`；圓角 `rounded-full`；陰影 `0 2px 8px rgba(168,120,42,0.3)` |
| hover（桌機） | 漸層亮化 `linear-gradient(135deg, #F4D89A, #DDB466)`；陰影增強 `0 4px 12px rgba(168,120,42,0.4)` |
| 按下 / active | `scale 0.96`；漸層轉為 `linear-gradient(135deg, #D4A853, #A8782A)`（偏 `gold.dark`） |
| 停用 | 不適用（下一步 / 完成永遠可點）；若需 disabled 則 `opacity 0.5` + `cursor not-allowed` |
| 載入 | 寫入 Firestore 旗標期間，「完成」鈕顯示旋轉 spinner（沿用 UserMenu 登出鈕的 spinner SVG：金色 `#D4A853`，`animate-spin`），文字暫隱或改為留白；spinner 不應阻斷退場過久（見「與 UX 對齊」） |

**次按鈕（Secondary）—— 「上一步」**

| 狀態 | 樣式 |
|------|------|
| 預設 | 透明背景；文字 `#8B6E5A`；`font-sans` `14px` `font-weight 500`；內距 `8px 14px`；圓角 `rounded-full`；邊框 `1px solid rgba(212,168,83,0.3)` |
| hover（桌機） | 背景 `rgba(212,168,83,0.08)`（沿用既有選單 hover 色） |
| 按下 / active | `scale 0.96`；背景 `rgba(212,168,83,0.14)` |
| 停用 | 第一站無「上一步」→ **不渲染該按鈕**（而非顯示 disabled 狀態），底部列只剩主按鈕，靠右對齊 |

**文字鈕（Text / Tertiary）—— 「略過導引」**

| 狀態 | 樣式 |
|------|------|
| 預設 | 無背景、無邊框；文字 `#C4A882`；`font-sans` `13px` `font-weight 400`；文字帶 `1px` 同色底線或無底線（見下）；內距 `4px 6px` |
| hover（桌機） | 文字轉 `#8B6E5A`（加深），底線浮現 |
| 按下 / active | `opacity 0.7` |
| 措辭 | 固定為 **「略過導引」**（總指揮裁示） |

### 5.2 按鈕配置（底部列布局）

底部列為 `flex justify-between`，左側進度指示、右側按鈕群。「略過導引」位置特殊：

- **「略過導引」** 不放右側按鈕群，改置於**說明卡右上角**，作為常駐關閉入口（每站都有，對應 FR-7.1 / AC-25）。
  - 右上角樣式：`13px` 文字「略過導引」＋ 左側一個 `12px` 的細線 `✕` 圖示，`color #C4A882`，`gap 4px`。
  - 距卡片上緣 `12px`、右緣 `14px`。hover 加深至 `#8B6E5A`。
  - 放右上角的理由：與業界 coachmark 慣例一致、不與「下一步」競爭視線、每站恆定位置好預期。
- **右側按鈕群**（底部列）：
  - 第一站：`[下一步]`（僅主按鈕，靠右）。
  - 中間站：`[上一步] [下一步]`，`gap 8px`，上一步在左。
  - 最後一站：`[上一步] [完成]`。
- 主按鈕永遠在最右側，是視覺重心；次按鈕在其左。

### 5.3 點遮罩空白處是否關閉

- **視覺建議：不要**讓點空白遮罩直接關閉教學（避免誤觸中斷）。明確關閉入口已有右上角「略過導引」。
- 此為體驗決策，最終交 UX 拍板（對應 FR-7.4，列入「與 UX 對齊」）。

## 六、入口按鈕「功能導引」

需與既有選單項目視覺**完全一致**，只是多一列。

### 6.1 手機 — UserMenu 下拉選單項目

插入位置由 UX / 需求決定（FR-2.2 僅要求「加入選單項目」）。視覺規格：

- 完全沿用 UserMenu 既有選單列樣式：
  - `className="w-full flex items-center gap-3 px-4 py-3.5 font-sans text-sm transition-colors duration-150"`
  - 文字色 `#8B6E5A`，下邊框 `1px solid rgba(212,168,83,0.15)`（若非選單最後一列）。
  - hover：背景 `rgba(212,168,83,0.08)`（與「每日提醒設定」「加到主畫面」列一致）。
  - 按下：沿用容器既有行為（選單列無額外 active scale）。
- **圖示**：`16×16` SVG，`stroke #8B6E5A`，`strokeWidth 1.5`，線條風格與既有選單圖示一致。
  - 建議圖示：羅盤 / 指南針 或 路標 意象（呼應「導引」）。具體圖示交美術設計；UI 規格要求尺寸、描邊、顏色與既有選單圖示統一。
- **文字**：「功能導引」。
- 不加任何「NEW」標記（EX-6：老使用者已被自動教一次，無需新功能標示；對應待釐清問題 6）。

### 6.2 桌機 — Sidebar `UserSection` 彈出選單項目

## 九、與 UX 設計師需對齊的事項

撰寫時尚無 `ux-flow.md`，以下視覺決策依賴 UX 動線確認：

1. **說明卡擺位演算法**：本文件給「優先序與安全邊界」，實際每站的最終方位需與 UX 站點動線一起定案。
2. **點遮罩空白處是否關閉**：UI 建議「不可」，最終由 UX 拍板（FR-7.4）。
3. **「略過導引」位置**：UI 定在說明卡右上角常駐。若 UX 希望在第一站額外更顯眼地提示跳過，需討論是否加第一站專屬提示。
4. **選單展開與遮罩進場時序**：站⑤⑥⑦（桌機⑤）需先展開選單再挖空（EX-10）。展開動畫期間遮罩 / 說明卡如何過場，需 UX + 架構師定義時序，視覺上挖空框會用補間動畫跟隨。
5. **「完成」鈕 spinner 等待**：若 Firestore 寫入較慢，spinner 不應讓使用者卡住。建議「樂觀關閉」——點完成立即退場，旗標背景寫入（EX-4 已允許寫入失敗降級）。此為動線決策，交 UX / 架構師。
6. **入口按鈕在選單中的插入順序**：FR-2.2 未指定手機版位置，需 UX 決定排在「每日提醒設定」之上或之下。
7. **卡片互動站說明卡置中時的視覺**：大目標站隱藏箭頭、靠光暈指向，需 UX 確認此體驗可接受。
