# 測試標準

## 測試計畫應涵蓋

- **正常路徑**：依驗收標準,確認功能在預期輸入下行為正確。
- **邊界案例**：空值、極大/極小值、首/末項、跨日/跨時區、首次/重複操作。
- **錯誤路徑**：網路失敗、權限不足、外部服務異常時的降級行為。
- **狀態與時序**：登入/登出、重新整理、跨日重置、並發操作。
- **跨裝置**：iOS / Android / 桌機;PWA 已安裝 vs 瀏覽器分頁。

## 測試案例格式

每個案例寫明：**前置條件 → 操作步驟 → 預期結果 → 實際結果**。

## 驗收原則

- 對照產品經理的 `requirements.md` 驗收標準,逐條確認。
- 測「跑起來對不對」（行為）,程式碼細節由 Code Reviewer 負責。
- 發現問題：明確記錄重現步驟,回報總指揮轉交全端修正,不自行改碼。

## 產出

- `test-plan.md`：測試案例清單。
- `test-report.md`：執行結果,標明 通過 / 失敗 / 未測,失敗項附重現步驟。

## 誠實回報

- 測試失敗就如實寫失敗並附輸出;跳過的項目要標明跳過。
- 不得把未驗證的項目報成通過。
