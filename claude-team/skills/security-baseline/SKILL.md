# 安全基準

## 機密與金鑰

- API 金鑰、服務帳戶、密鑰**絕不寫進程式碼或進版控**,一律走環境變數。
- 前端（`VITE_` 開頭）的環境變數會被打包公開 —— 只放可公開的值。
- 真正的機密只放後端（Serverless 環境變數）。
- 文件、log、commit 訊息中不得出現機密內容。

## 身分驗證與授權

- 後端端點要驗證呼叫者身分（Firebase ID token 或共用密鑰）。
- 驗證失敗回傳明確狀態碼（401 / 403）,不洩漏內部細節。
- 不信任前端傳來的身分宣稱,一律後端再驗。

## 資料庫規則（Firestore）

- 預設拒絕;只開放使用者存取「自己的」資料。
- 規則變更要經資安審查。

## 端點與輸入

- 對外端點限制 HTTP method、驗證輸入、處理例外不洩漏堆疊。
- 測試 / 除錯用端點要能在正式環境**確實關閉**（環境變數控制）。

## 相依套件

- 留意已知漏洞;不引入來路不明的套件。

## 審查產出

- `security-review.md`：列出檢查項目、發現的問題、風險等級、建議修法。
- 高風險問題必須在上線前解決。
