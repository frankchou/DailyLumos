# Commit 與文件準則

## 鐵則：三份系統文件一起更新

**每一次有意義的改動,都必須同批更新這三份文件,不可只改其中一兩份：**

1. `docs/系統架構.md` —— 系統由哪些部分組成、各部分職責
2. `docs/系統機制.md` —— 各功能實際怎麼運作
3. `docs/版本紀錄.md` —— 每次改動的紀錄

> 描述「現況」的架構/機制兩份要保持與程式碼一致;
> 版本紀錄記錄「歷史」,只增不改舊條目。
> 三份脫節會造成資訊不同步 —— 這是不可接受的。

## 版本紀錄條目格式

每筆改動在 `版本紀錄.md` 最上方新增,**最新在最上面**：

```
### HH:MM — 一句話標題
- **更新內容**：詳細、白話、一般人看得懂地說明「更新了什麼功能」。
- **更新檔案**：列出動到的檔案（只列檔名,不逐檔說明改了什麼）。
- **Git 紀錄**：`<commit hash 前 7 碼>`
```

- 時間用**台灣時間（UTC+8）**。
- 日期分隔用 `## YYYY-MM-DD`。

## Commit 訊息規範

- 格式：`type(scope): 摘要`，type 用 feat / fix / docs / chore / refactor / perf。
- 摘要精簡、講清楚做了什麼。內文說明「為什麼」。
- 結尾加上：
  ```
  Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>
  ```

## 提交流程

1. 確認 `npx tsc -b` 通過。
2. 三份文件已同步更新。
3. commit；**push 需經使用者同意**,不擅自 push。
4. 若在預設分支（main）上,原則上先開分支。
